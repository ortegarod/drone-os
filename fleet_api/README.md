# DroneOS Fleet API

The one door into the drones. The web UI, the `droneos` CLI, SDK scripts and the AI agent all use this API, and it's the only part of the command center that talks to drone_core (over rosbridge).

```
Web UI ─┐
CLI ────┼──> Fleet API (VPS :8090) ──rosbridge──> drone_core (the sim host today, the drone later)
SDK/AI ─┘
```

## What it does
- **Drones:** finds every `/<name>/drone_state` topic, keeps the latest state, and reports a drone offline if its state goes quiet for 3 s.
- **Positions in operator terms:** meters north/east of home, and altitude in meters above where the drone last sat disarmed.
- **One pilot per drone:** the first command takes control. Other operators get `409` until control is released, taken over with `force`, or idle for 15 min. **Safety commands** (`land`, `return_home`, `kill`) work for any logged-in operator, at any time.
- **Command log:** every command, refusal and failure is written to JSONL with operator, drone, args and result.
- **Operators and roles:** every token belongs to an operator with a role: **admin** (everything, incl. operators and plugins), **pilot** (fly, start/stop jobs), **viewer** (watch only: drones, log, reports). Two sources:
  - **accounts**, managed through the API by an admin (`droneos operators add NAME --role pilot`, or the Dev tab): token generated by the API, shown once, stored as a sha256 (`FLEET_API_OPERATORS`, default `~/.local/state/droneos/fleet_api_operators.json`). Reset a lost token with `droneos operators token NAME`; `remove` revokes it and releases any drone they held.
  - the **tokens file** `{"<token>": "<operator>"}` (`FLEET_API_TOKENS`, default `~/.config/droneos/fleet_api_tokens.json`, mode 600): bootstrap operators and services (the bundled plugins). Those in `FLEET_API_ADMINS` are admins, the rest pilots.
  - Installed plugins fly with their own token (pilot).

## API (v1)
All endpoints except `/health` need `Authorization: Bearer <token>`.

| Method | Path | Body | |
|---|---|---|---|
| GET | `/api/v1/health` | | connection + drone count |
| GET | `/api/v1/me` | | who am I: `{"operator", "role"}` |
| GET/POST | `/api/v1/operators` | POST `{"name", "role"}` | admins: everyone with access / new account (reply has its token, once) |
| PATCH/DELETE | `/api/v1/operators/{name}` | PATCH `{"role"}` | admins: change role / remove an account |
| POST | `/api/v1/operators/{name}/token` | | admins: new token for an account (old one stops working) |
| POST/DELETE | `/api/v1/plugins[/{id}]` | manifest | admins: install/update or remove a plugin (see docs/plugins.md) |
| GET | `/api/v1/drones` | | fleet list (position, battery, GPS, health, controller) |
| GET | `/api/v1/drones/{name}?raw=true` | | one drone (+ raw drone_core state) |
| POST | `/api/v1/drones/{name}/takeoff` | `{"altitude": 10}` | arm and climb straight up |
| POST | `/api/v1/drones/{name}/goto` | `{"north": 20, "east": 0, "altitude"?: 15, "heading"?: 90}` | fly to point (must be flying) |
| POST | `/api/v1/drones/{name}/land` | | land here |
| POST | `/api/v1/drones/{name}/return_home` | | fly home and land |
| POST | `/api/v1/drones/{name}/arm` / `disarm` | | |
| POST | `/api/v1/drones/{name}/kill` | | **cuts motors, drone falls** |
| POST | `/api/v1/drones/{name}/patrol` | `{"route": [[40,0],[40,30]], "altitude": 15, "loops": 2, "hold"?: 0, "radius"?: 2}` | takes off if needed, runs the route **onboard**, then home + land |
| GET | `/api/v1/drones/{name}/patrol` | | onboard patrol progress (`?raw=1`: drone_core's mission status as is) |
| GET | `/api/v1/plugins` | | installed plugins (manifests in `$FLEET_API_PLUGINS/*/droneos-plugin.json`) |
| GET/POST/PATCH/DELETE | `/api/v1/drones/{name}/job` | POST `{"plugin": "patrol", "args": {...}}` | the drone's one job: start (the plugin takes control), update/end (plugin only), anyone else ending it = stopped |
| GET | `/api/v1/jobs[?drone=&plugin=]`, `/api/v1/jobs/active` | | finished jobs / running jobs per drone |
| any | `/api/v1/plugins/{id}/...` | | proxy to the plugin's own endpoints (the plugin sees `X-DroneOS-Operator`) |

Patrol is plugin #1 (`plugins/patrol`): routes, reports and photos moved there (`/api/v1/plugins/patrol/routes`, `/drones/{name}/route`, `/reports`, `/reports/{id}/photos/{n}.jpg`, `/drones/{name}/pause|resume`). The `patrol` command above is the low-level drone command the plugin uses.
| POST | `/api/v1/drones/{name}/control` | `{"force": false}` | take control |
| DELETE | `/api/v1/drones/{name}/control` | | release control |
| GET | `/api/v1/log?limit=100&drone=drone1` | | command log, newest first |
| WS | `/api/v1/telemetry?token=…&hz=5` | | pushes `{"type":"fleet","drones":[…]}` |

Commands return as soon as drone_core accepts them. Watch telemetry to see the result. Altitudes are limited to 2–120 m.

## Run
```bash
cd fleet_api && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest httpx
.venv/bin/python -m pytest -q                       # unit tests (fake fleet, no ROS needed)
ROSBRIDGE_HOST=<sim host> .venv/bin/uvicorn app:app --host 127.0.0.1 --port 8090
```
On the VPS: the `fleet_api` service in `docker/vps/docker-compose.vps.yml`.

## Not yet
- No passwords or SSO: an operator logs in with their token (the Command Center's login screen, or `~/.config/droneos/client.json` for the CLI). On the Tailscale dev setup the browser can auto-log in as one operator (AUTO_LOGIN_OPERATOR).
- Roles are fleet-wide (no per-drone permissions yet).
